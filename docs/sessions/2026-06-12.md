## What happened

1. **Duplicate-open bug fixed** (the owner accidentally opened one position
   5×): `openPaperTrade` is now a `useActionState` action that returns
   state instead of throwing (prod masks thrown server-action errors — that
   silence was the root cause). The form (`PaperTradeForm`, client half of
   the widget) disables the button while pending, shows the exact fill on
   success (`describeFill` in explain/copy.ts), and carries a server-minted
   idempotency UUID; the unique index `paper_trades_idem_uq` makes any
   retry (double-tap, back button) a no-op that echoes the original fill.
   The key rotates client-side after success so deliberate repeats work.
2. **Profile system** (owner request: "a few ppl try it out, simple email
   sign up" — decided: email + shared invite code, own book each):
   `profiles` table, `src/lib/profile.ts` (HMAC-signed `ss_profile` cookie,
   key = ADMIN_TOKEN; no email verification by design), sign-up/sign-in is
   one form on `/paper`; admin token path unchanged and owns the
   `profileId NULL` book. All trade actions check ownership. New
   `INVITE_CODE` env var; unset = sign-ups disabled.
3. **Auto-settlement**: verified live first
   (`scripts/check-kalshi-settlement.ts`): settled Kalshi markets are
   status `finalized` + result `yes|no`; `determined` is an intermediate
   inside the settlement timer (do NOT settle on it); `?status=settled`
   works, `?status=finalized` 400s; `GET /markets?tickers=` returns settled
   tickers. New hourly `settle-paper` job re-fetches exactly the tickers
   open trades sit on and settles only on `finalized` + binary result,
   via shared race-safe `settleOpenTrade()` (`status='open'` guard);
   skip-counters in `sync_runs`. Manual buttons remain as override.
   `markets.result` column added; sync-catalog never writes it.
4. **Widget UX**: share preset chips (25/100/250/500), live cost/fee/edge
   breakdown before submit, inline thin-book warning with `executableUsd`,
   `inputMode="numeric"` for phone keyboards.
5. **/paper book**: two-tap close with preview (bids − exit fees, P&L)
   from the existing `markToMarket` (now exposes per-leg bids/fees);
   per-trade "since you entered" spread chart via new
   `getSpreadHistoryRange()` windowed to the holding period.
6. **/admin/matches**: per-link current mids + Δ gap (inversion-aware,
   amber at ≥5¢), "showing 25 of N", outbound platform links on titles.
7. Migration `drizzle/0002_profiles_settlement.sql` + generic

## Addendum: code review + fixes (post-launch)

Owner ran /code-review seeded with an external LLM review. Outcome:

- **Fixed — idempotency scoping** (`actions.ts`): duplicate-detection
  queries now filter by the requesting identity's profileId; a replayed
  key from another identity gets a neutral error, never the other user's
  fill. Verified live with two tester profiles replaying one key.
- **Fixed — executable-depth side bug** (`spread.ts`, PRE-EXISTING): both
  platforms store books from the YES perspective, so the NO-buying leg of
  an arb crosses the BID side; the gate was reading ask depth for it.
  `invertQuote`'s depth swap composes correctly with the new rule.
- **Fixed — status vocabulary** (`settle-paper`): writes `closed` (app
  vocab), not Kalshi's `finalized`; result column carries the outcome.
- **Fixed — usd2 triplication** (import from explain/copy) and the
  O(trades×markets) loop in settle-paper (prebuilt Map).
- **External review triage**: its Polymarket "fake NO prices" headline was
  wrong (binary-CLOB complements are real liquidity) but adjacent to the
  real depth-side bug; cron-cadence claim refuted (GH Actions pinger is

  vitest for the pure math (spread/fees/settlement/sealing), dedicated
  PROFILE_SIGNING_KEY instead of reusing ADMIN_TOKEN.
