     of mislabeling bot closes as `"manual"`.

## Diagnosis: "Run now" skipped all 47, opened 0

Every run reported **47 skipped / 0 opened**, all under one chip *"resolves too
far out."* We tried disabling the gate by setting
`AUTO_TRADER_MAX_DAYS_TO_RESOLVE=0` and re-ran — still 47. Reading the code gave
a **deterministic** answer:

- `config.ts:47` `Number(env ?? 90)` → `0`; `autoTrader.ts:177` `horizonMs =
  …>0 ? … : null` → `null`; `autoTrader.ts:183` `if (horizonMs !== null)` wraps
  the **whole** skip. So if `0` were live, "too far" would be **0**. It was 47 ⇒
  **the env change never reached the running deployment** (wrong Vercel scope,
  or no redeploy — env vars bake in at deploy time).
- The chip also **conflated two failures**: a **missing** close date
  (`!closeAt` — a possible sync-catalog gap) and a **genuinely far** date both
  read as "resolves too far out", so we couldn't tell which we were hitting.

**Fix `c5c7db6`:** split the gate into two reasons — `skippedNoCloseDate`
("no close date") vs `skippedTooFar` ("resolves too far out") in
`src/lib/autoTrader.ts`, with the matching label in
`src/app/admin/auto-trader/page.tsx`. Behavior-preserving (same pairs skipped),
but the next run now says **why**.
